# 정확한 시계

KRISS(한국표준과학연구원) 표준시 NTP 서버와 직접 비교해서 보정한 시각을 숫자만 크게 보여주는 윈도우 시계.
PC 시계 설정은 건드리지 않습니다(관리자 권한 불필요).

## 실행

`PreciseClock.exe` 더블클릭. (.NET 10 Desktop Runtime 필요)

빌드:

```bash
dotnet publish -c Release
```

결과물: `bin\Release\net10.0-windows\win-x64\publish\PreciseClock.exe`

## 조작

| 입력 | 동작 |
|---|---|
| 드래그 | 창 이동 (가장자리 드래그로 크기 조절) |
| 더블클릭 / F11 | 전체 화면 |
| T | 항상 위 켜기/끄기 |
| M | 밀리초 자릿수 바꾸기 (3자리 → 2자리 → 1자리 → 끔) |
| I | 하단 상태줄 켜기/끄기 |
| C | 색상 설정 (배경·시각·밀리초·상태줄 색과 투명도, 빠른 테마) |
| R | 지금 다시 맞추기 |
| Esc | 전체 화면 해제 |
| 우클릭 | 위 기능 메뉴 |

## 정확도

- `ntp.kriss.re.kr` → `time.kriss.re.kr` → `time2.kriss.re.kr` 순서로 시도
- 시작 시 2초 간격 6회, 이후 2분마다 4회 측정 → 왕복지연이 가장 짧은 측정값 채택
- 측정 사이에는 PC 내부 시계의 빠르기 차이(이 PC는 약 46ppm, 5분에 14ms)를 추정해서 보정
- 네트워크가 잠깐 느려서 덜 정확한 측정은 버리고 기존 보정값을 유지
- 상태줄의 `오차 ±n ms` = 지금 화면 시각이 틀릴 수 있는 최대 범위 (측정 오차 + 그 뒤로 쌓였을 수 있는 만큼)
- 인터넷이 끊기면 마지막 보정값으로 계속 표시하고 15초 → 30초 → 1분 → 2분 간격으로 다시 시도
- 예상 못한 오류는 `%APPDATA%\PreciseClock\error.log` 에 기록 (프로그램은 꺼지지 않음)
- 화면은 모니터 주사율마다 갱신(60Hz면 약 16ms 간격). 모니터 자체의 표시 지연(보통 1~2프레임)은 보정하지 않음
- 아직 못 맞췄거나 연결 실패 시: 시각이 회색(PC 시계)으로 표시되고 상태줄이 빨갛게 바뀜

## 옵션

- `--log` : 측정 기록을 `%APPDATA%\PreciseClock\sync.log` 에 저장
- `--server a,b` : NTP 서버 목록 변경

설정(창 위치·크기·토글)은 `%APPDATA%\PreciseClock\settings.json` 에 저장됩니다.

KRISS 안내에 따라 개인 확인용으로만 사용하세요(상업적 이용·정밀 산업 용도 불가).
